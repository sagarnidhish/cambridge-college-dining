# Cambridge College Dining Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and publicly deploy a live-on-reload GitHub Pages dashboard for Churchill College and St Edmund's College dining availability, times, menus, notices, freshness, and official verification links.

**Architecture:** A framework-free TypeScript/Vite application fetches the colleges' public WordPress REST endpoints in the browser. College-specific adapters normalize source data into one strict daily model, while an orchestration layer isolates failures and provides visibly stale local-storage fallbacks. The UI renders only normalized data through safe DOM APIs and embeds or links St Edmund's official menu PDFs.

**Tech Stack:** Node.js 20.19 or newer, npm, TypeScript 7.0.2, Vite 8.1.5, Vitest 4.1.10, jsdom 27.4.0, vanilla HTML/CSS/DOM APIs, GitHub Actions, GitHub Pages.

## Global Constraints

- Use `Europe/London` for the selected date, weekday, and all user-facing freshness times.
- Fetch official data on every full page load and every explicit Refresh action with browser caching disabled.
- Do not claim data is fresher than the response currently served by each college's own server or CDN.
- Every college/day view must visibly include weekday, full date, breakfast, brunch, lunch, dinner, availability, serving time, menu status or content, meal notes/restrictions, published general notices, last-checked time, and an official source link.
- Availability values are exactly `available`, `closed`, or `unknown`.
- Never infer closure from an empty menu cell; missing or ambiguous information must remain explicit.
- A dated weekly exception overrides a recurring timetable.
- Never inject college-provided HTML into the application DOM; parse it and render text with owned DOM elements.
- A cached fallback must be tied to the exact college and selected date and marked `stale` with its original retrieval timestamp.
- One college's failure must not prevent the other college from rendering.
- No application server, central database, user account, notification system, historical archive, or automated PDF text extraction is part of version one.
- External links open in a new tab with `rel="noopener noreferrer"`.
- Keep source clients, college adapters, storage, orchestration, and rendering in separate focused modules.

```ts
export interface WordPressPage {
  id: number;
  modified: string;
  link: string;
  title?: { rendered: string };
  content: { rendered: string; protected: boolean };
}

export interface WordPressPost extends WordPressPage {
  date: string;
}

export function normalizeWhitespace(value: string): string {
  return value.replace(/\u00a0/g, " ").replace(/\s+/g, " ").trim();
}

export function htmlLines(element: Element): string[] {
  const clone = element.cloneNode(true) as Element;
  clone.querySelectorAll("br").forEach((br) => br.replaceWith("\n"));
  return (clone.textContent ?? "").split(/\n+/).map(normalizeWhitespace).filter(Boolean);
}
```
